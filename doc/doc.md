## Overview

SkillHub is a **Git-backed knowledge engine for AI agent skills**. The engine code (this repository) is decoupled from content: point `--repo` at any repository that contains a `knowledge/` directory, and the engine indexes and serves that content over MCP. Markdown is the single source of truth; the index is rebuilt from disk and can be recreated at any time.

The engine ships a ready-to-use `knowledge/` category skeleton, so you can start with zero external dependencies — or clone an existing knowledge repository and point `--repo` at it.

## Requirements & Installation

- Python 3.11 or newer
- [uv](https://docs.astral.sh/uv/) — the only tooling dependency (uv provisions the interpreter if needed)

```bash
git clone <your-engine-repo-url> context-hub
cd context-hub
uv sync          # installs dependencies and creates the environment
```

Two entry points are installed:

| Command | Purpose |
| --- | --- |
| `uv run skillhub ...` | Local operator CLI (validate / search / status / reindex) |
| `uv run skillhub-mcp ...` | MCP server (stdio or streamable-http) |

## Running the Service

### Shared HTTP mode (recommended for personal machines)

One resident service, one address shared by every client:

```bash
uv run skillhub-mcp --repo /path/to/your-knowledge \
    --transport streamable-http --host 127.0.0.1 --port 8765
```

Clients connect to `http://127.0.0.1:8765/mcp`. On Windows, `scripts\start-skillhub-mcp.bat <knowledge-repo-path> 8765` does the same. For autostart at logon (silent, background) see the Windows Autostart section below.

### stdio mode (client-launched)

Omit `--transport` (the default is `stdio`) and configure your client to start the server; see Client Setup.

### Configuration via environment variables

| Variable | Default | Meaning |
| --- | --- | --- |
| `SKILLHUB_REPO` | current directory | Repository root containing `knowledge/` |
| `SKILLHUB_KNOWLEDGE_DIR` | `knowledge` | Knowledge directory relative to the repo root |
| `SKILLHUB_TRANSPORT` | `stdio` | `stdio` or `streamable-http` |
| `SKILLHUB_HOST` | `127.0.0.1` | Bind address (HTTP mode) |
| `SKILLHUB_PORT` | `8765` | Bind port (HTTP mode) |

## Client Setup

Convention: the `command` launches the **engine** (context-hub) and `--repo` points at **your knowledge base**. Use forward slashes for Windows paths, e.g. `D:/my-skills`.

HTTP mode (all clients):

```json
{ "mcpServers": { "skillhub": { "type": "http", "url": "http://127.0.0.1:8765/mcp" } } }
```

stdio mode:

```json
{
  "mcpServers": {
    "skillhub": {
      "type": "stdio",

      "args": [
        "--directory", "/path/to/context-hub",
```

## CLI Reference

All commands take `--repo` (default: current directory) and `--knowledge-dir` (default `knowledge`).

```bash
uv run skillhub --repo /path/to/knowledge validate
uv run skillhub --repo /path/to/knowledge search "发布" --tag 绘丹青 --limit 5
uv run skillhub --repo /path/to/knowledge status
uv run skillhub --repo /path/to/knowledge reindex
```

| Subcommand | Behavior |
| --- | --- |
| `validate` | Rebuilds the index and reports `{"valid", "documents", "issues"}`. Exit code 1 when any issue exists; invalid documents are excluded from the live index until fixed |
| `search <query>` | Keyword search over metadata and content. Filters: `--type {skill,prompt,workflow,template,rule}` (repeatable), `--tag <name>` (repeatable), `--limit` (default 5, clamped to 1–20) |
| `status` | Document count by type, validation issues, watcher flag, index time, and Git status of the knowledge directory |
| `reindex` | Forces a full in-memory rebuild and reports `{"indexed", "invalid", "indexed_at"}` |

JSON output goes to stdout; errors to stderr with exit code 2.

## MCP Tools Reference

| Tool | Purpose | Returns full content |
| --- | --- | --- |
| `search_knowledge(query, types?, tags?, limit?)` | Keyword search | No — compact hits |
| `recommend_knowledge(task, types?, tags?, limit?)` | Recommend candidates for a described task | No — compact hits |
| `list_knowledge(type?, tags?, offset?, limit?)` | Browse the catalog with pagination | No |
| `get_knowledge(id, resource?)` | Load one full document; fetch one skill sub-resource | Yes |

Usage pattern:

1. `search_knowledge` / `recommend_knowledge` returns up to `limit` summaries (`id`, `type`, `title`, `description`, `tags`, `path`, optional `version`, `resources_count`) plus a `next_step` hint.
2. Pick the best `id` and call `get_knowledge(id)` — for a skill this returns the `SKILL.md` body, front matter as `metadata`, keywords, and a **resource manifest** (`references/`, `scripts/`, `templates/` entries with size and media type).
3. If the skill needs a sub-resource, call `get_knowledge(id, resource="references/xxx.md")` for that single file (paths may omit the leading `@`; backslashes are normalized).

Safety limits: `search`/`list` limits are clamped (20 / 100 max), sub-resources are capped at 1 MB, resource content must be UTF-8 text, and resource paths cannot escape the skill package. Unknown ids or resources raise a clear error.

Search relevance is lexical and deterministic: weighted fields `id > title > tags > keywords > description > content`, with phrase bonuses; Chinese text is tokenized into full runs plus single characters and bigrams. Filter by knowledge type and/or tags when you need precision.

## Skill & Document Format

- A **packaged skill** is a directory `knowledge/skills/{skill-name}/SKILL.md` with optional `references/`, `scripts/`, `templates/` sub-directories. Category directories above the package are free-form (Chinese names, any depth) and their names become searchable tags.
- Required skill front matter: `description`, `description_zh`, `description_en`, `version`, `author`. `name` is optional and defaults to the directory name; when present it must equal the directory name, be unique, and be ASCII (letters/digits/`.`/`_`/`/`/`-`, starting alphanumeric). `display_name`, `category`, `allowed-tools`, `disable-model-invocation`, `user-invocable`, `tags`, `keywords` are optional.
- **Other knowledge types** (`prompt`, `workflow`, `template`, `rule`) are single Markdown files anywhere outside `knowledge/skills/` with required `id`, `type`, `title`, `description`.
- Body references like `@references/api.md` are validated against the package; broken references fail validation for that file.
- ⚠️ Quote any front-matter value containing an English colon (`: `), or YAML parsing fails and the document is skipped.

Run `uv run skillhub validate` before committing. The full spec lives in [../docs/content-format.md](../docs/content-format.md) (English: [../docs/content-format.en.md](../docs/content-format.en.md)).

## Trae: Making the Agent Search Proactively (router skill)

Content is only discoverable through retrieval, so Trae agents need to be told to search first. The repository ships a mandatory-first router skill at `.trae/skills/skillhub-router/SKILL.md`: any task must first call `recommend_knowledge` / `search_knowledge`; matched knowledge wins over built-in skills.

Install it for Trae (either way, then restart Trae):

- **Project level** — copy `.trae/skills/skillhub-router/` into the target project root
- **Global level** — copy it into Trae's global skills directory (Windows CN: `%USERPROFILE%\.trae-cn\skills\...`)

If the agent still does not search proactively, turn the same content into a Trae **rule** (fully injected every session) — behavior is equivalent.

## Windows Autostart

Silently start the shared HTTP service at logon so clients never need stdio configs:

```powershell
# 1. Create scripts\start-skillhub.vbs (adjust paths)
#    Set shell = CreateObject("WScript.Shell")
#    shell.Run """D:\context-hub\scripts\start-skillhub-mcp.bat"" D:\my-skills 8765", 0, False
# 2. Put it in the Startup folder
$startup = [Environment]::GetFolderPath('Startup')
Copy-Item D:\context-hub\scripts\start-skillhub.vbs "$startup\SkillHub-MCP.vbs"
```

Manage:

```powershell
Start-Process wscript.exe -ArgumentList '"D:\context-hub\scripts\start-skillhub.vbs"'
Get-NetTCPConnection -LocalPort 8765 -State Listen     # LISTENING = success
taskkill /PID <PID> /F                                  # stop; restarts at next logon
```

Alternatives: Task Scheduler (logon trigger) or NSSM as a Windows service (no logon needed, crash auto-restart).

## FAQ

**Q: The agent reports no relevant skill / only sees built-in skills.**
A: Verify `skillhub` is connected with all 4 tools visible in the MCP panel; confirm the server was started with `--repo` pointing at your knowledge base and that `validate` passes. SkillHub content requires an active search (Trae: install the router skill).

**Q: `validate` fails / some skills are not indexed?**
A: Common causes: required fields missing or unquoted English colons; `name` not matching the directory or duplicated; or the body referencing a nonexistent `@references|scripts|templates/...` file. Fix, then validate again.

**Q: Do I need to restart after editing the knowledge base?**
A: No. The watcher rebuilds the index automatically and `git pull` updates are picked up too (read-time fingerprint checks are the correctness fallback).

**Q: Port already in use / server will not start?**
A: `Get-NetTCPConnection -LocalPort 8765 -State Listen` shows the blocker; change the port via the bat script's second argument or `--port`.

**Q: Switch to or add another knowledge base?**
A: Change `--repo` (or the environment variables above) and restart the service.
